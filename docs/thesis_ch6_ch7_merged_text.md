# 第一部分 第六章（QPLY 格式与 WebGL 渲染系统）——按当前代码重写

## 6.1 本章总览

第 4 章与第 5 章分别从点数与单点属性两个维度完成了压缩方法设计：前者通过预算感知剪枝控制高斯数量，后者通过共享基低秩分解与分组标量量化降低单个高斯的属性存储开销。压缩算法本身并不等价于端侧可部署：对移动端 WebGL 而言，压缩产物还必须满足三个工程条件——能以单文件形式高效传输、能被浏览器端解析器稳定识别、能在不依赖额外神经网络推理与计算着色器的前提下实时渲染。本章给出满足这三项条件的部署出口。

本章在 gsplat.js 基础上扩展 WebGL 2.0 渲染管线，设计并实现 QPLY（Quantized Half PLY）文件格式。QPLY 在 reduced-3DGS 的量化 PLY 组织方式上做兼容扩展，既支持标准 QPLY，也支持内嵌共享基矩阵的低秩 QPLY。渲染端提供两条互斥可选的三阶球谐求值路径：**缺省路径**在顶点着色器中完成系数解包与球谐求值；**颜色缓存路径**把球谐求值整体移入一次全屏片元遍，结果写入半精度颜色缓存纹理，主 pass 顶点只按下标取回颜色。低秩属性对应两条处理路径：**加载期展开路径**在加载阶段把低秩系数展开为 45 维系数后打包；**渲染期求值路径**只上传低秩系数与共享基，45 维系数在片元求值循环中按秩累加得到。两条低秩路径的文件格式完全相同，可在同一份模型上逐像素对拍。

## 6.2 文件格式设计

QPLY 在标准 PLY 基础上继承并扩展 reduced-3DGS 的量化格式约定：按 SH 阶数预留四组顶点元素，分别对应 0 至 3 阶球谐系数，解析端据此识别各阶 rest 系数的存储边界。当前实现统一导出三阶高斯，最高阶元素承载全部顶点数据，低阶元素暂为空占位，以保留与 reduced-3DGS 的格式兼容。

每个高斯存储位置（三个半精度浮点，共 6 字节）与各属性组的 8 位码本索引；文件另附共享标量码本，每个属性组对应一份 256 项的半精度浮点码表，涵盖尺度、旋转四元数、DC 颜色、三阶 SH 各阶系数与不透明度。渲染时按索引查表还原浮点属性。

**低秩 QPLY 分支。** 当训练端启用第 5 章的共享基低秩分解时，导出器额外写入一个共享基元素，存放 FP16 的共享基矩阵 $W\in\mathbb{R}^{r\times45}$，并在文件头记录秩 $r$。顶点数据中原本对应 45 维 rest 系数的索引替换为 $r$ 维低秩系数索引。当前实现的 $r$ 上限为 7，文件头中的秩与渲染端编译期常量一致，解析端对不足的槽位补 0，使定长循环不引入误差。

**两种变体的文件体积。** 同一份训练模型可分别导出标准 QPLY（$r=45$）与低秩 QPLY（部署档 $r=7$），点数为同一个数，差别只在每点字节数：

| 场景 | 高斯点数 | 标准 QPLY（$r=45$） | 低秩 QPLY（$r=7$） | 每点字节（标准 / 低秩） |
| --- | ---: | ---: | ---: | ---: |
| garden | 0.610 M | 37.83 MB（36.08 MiB） | 14.65 MB（13.97 MiB） | 62.0 / 24.0 |
| truck | 0.273 M | 17.0 MB（16.21 MiB） | 6.56 MB（6.26 MiB） | 62.2 / 24.0 |
| drjohnson | 0.432 M | 26.8 MB（25.56 MiB） | 10.38 MB（9.90 MiB） | 62.0 / 24.0 |

> 表注：体积按文件字节数除以 $10^6$ 取两位小数（括号内为除以 $2^{20}$ 的 MiB，列此仅为避免进制混用）。两列来自同一份模型的两份导出文件，点数完全相同；低秩档为 24 B/点，秩每提高 1、每点增加 1 字节。

QPLY 并非从零定义的私有格式，而是在 reduced-3DGS 量化 PLY 结构基础上的兼容实现：元素分组、属性排列与码本结构均与其保持一致或可兼容解析。因此同一文件既可由本文扩展后的渲染端加载，也能在保留兼容字段的情况下对接 reduced-3DGS 的解码路径。

## 6.3 纹理化存储与三阶球谐求值

量化属性的解码在 CPU 端加载期统一完成：各属性先按 8 位索引经码本查表还原为浮点值，其中 SH rest 系数再以 16 位半精度按位打包为 32 位无符号整数，以**整型纹理**上传 GPU。选择整型纹理并非由于 WebGL 2.0 不支持半浮点纹理采样（半浮点纹理属于其核心支持格式），而是出于取数效率与工程一致性两方面考虑：单个 `RGBA32UI` 纹素可容纳八个 16 位半精度系数，顶点着色器一次取数即可取回八个系数，较半浮点纹素明显减少取数次数；同时按位打包保证 CPU 打包与 Shader 解包两侧位级一致，也与既有属性纹理的整型组织方式一致。R、G、B 三个颜色通道各对应一张独立纹理，避免通道交错带来的解析复杂度。

球谐纹理宽度固定为 2048，高度随含 SH 的高斯数量向上取整。作为对照，部分已有方案把场景级 SH 系数整体组织为单张 8192 像素宽的浮点纹理，其单方向尺寸与浮点上传路径在移动端 WebGL 实现上的兼容性较差（实测现象见 6.5 节）；本方法按颜色通道拆分为三张宽度较小的整型纹理，规避该类风险。

**两条球谐求值路径。** 系数解包完成后的三阶球谐求值有两种实现，二者属性存储与解码完全一致，差别只在求值发生的位置，且都由 URL 开关显式选择：

- **缺省路径（顶点求值）**：SH 系数在顶点着色器中解包并逐项求值，颜色直接参与后续投影与混合。该路径不引入任何帧内中间纹理，实现最直接。此时每点 SH 纹理占用约 96 字节（4 个整型纹素用于打包系数，另 2 个纹素存放中心与协方差），以 0.610 M 点的 garden 计约 58.6 MB。
- **颜色缓存路径（片元求值，部署实测配置）**：三阶球谐求值整体移入一次全屏三角形的片元遍，求值结果以 `RGBA16F` 写入一张尺寸为 $2048\times\lceil N/2048\rceil$ 的颜色缓存纹理；主 pass 仍以实例化 `TRIANGLE_FAN` 绘制（每 splat 4 个顶点），但顶点侧只按索引从颜色纹理取回该点颜色。收益来自把逐点求值从"每 splat 4 个顶点各算一次"改为"每 splat 算一次"：在同会话 A/B 对照中该改动使吞吐提升约 1.43 倍，且两条路径的逐像素颜色一致性通过像素级闸门校验（PSNR 约 60 dB 量级，远高于 8 级像素差异阈值），说明输出等价、取舍只关乎性能。

颜色缓存路径的代价是每帧写入 $N\times8$ 字节（`RGBA16F`，每 splat 一个纹素；0.610 M 点约 4.88 MB/帧）。该帧内中间结果不属于模型文件体积，而属于运行期显存占用；当 SH 系数在相邻帧间不再变化时可显式冻结并复用上一帧结果（诊断臂，缺省关闭），缺省配置下每帧重新生产以保证视角相关外观随相机实时变化。启用该路径时，渲染端会先探测并启用渲染到半精度颜色附件所需的浮点颜色缓冲扩展，若上下文不支持则自动退回顶点路径。

| 项 | 缺省路径（顶点求值） | 部署实测配置（片元求值 + 低秩） |
| --- | --- | --- |
| SH 系数存储 | 整型纹理打包，约 96 B/点 ⇒ ≈ 58.6 MB（garden） | 低秩系数 rank 纹理（`RGBA32UI`）+ 共享基 uniform block（79 vec4，常量 1264 B） |
| 三阶 SH 求值位置 | 主 pass 顶点着色器 | 全屏三角形片元遍 → `RGBA16F` 颜色缓存（$2048\times\lceil N/2048\rceil$） |
| 颜色缓存开销 | 不使用 | 8 B/点 ⇒ ≈ 4.88 MB/帧（缺省每帧重生产） |
| 逐点变换 | 变换纹理逐点取样 | 跳过，改用 uniform 矩阵 |
| 颜色变换 | 颜色变换纹理 | 恒等 |
| 半精度 SH 诊断档 | 32 B/点 ⇒ ≈ 19.5 MB（开关缺省关闭） | — |

## 6.4 低秩属性的两条处理路径

低秩 QPLY 在加载与渲染侧对应两种处理方式，文件格式相同，差别在于 45 维 rest 系数在何处重建，均由开关显式选择。

**加载期展开路径。** 解析器在加载阶段解出 $r$ 维逐点低秩系数，与共享基相乘展开为 45 维 rest 系数后再打包进整型纹理。该路径的渲染期与标准三阶 SH 完全同构，代价是把一次矩阵重建放进首帧；解析模块对外提供"解析头部（读取低秩码本与共享基）"与"按顶点区间解码并重建"两个入口，后者可按 CPU 并发度切分为多个区间并行处理，各分片的结果以零拷贝方式回传主线程。

**渲染期求值路径（部署实测配置）。** 加载期只反量化 $r$ 维低秩系数并打包为 rank 纹理（`RGBA32UI`），**不进行显式的 45 维重建**；共享基以 uniform block 常驻 GPU（79 个 vec4，共 1264 字节，由秩上限 7 与 rest 维度 45 决定），45 维 rest 系数在片元求值循环中按秩累加得到。这样做的结果是加载阶段解析的数据量随秩 $r$ 下降，而重建代价被摊到每帧的求值循环里，不占用首帧；同时因为不再需要为 45 维系数分配整型纹理，显存占用由"每点约 96 字节"降到"每点 4 个低秩系数 + 一份常量共享基"。低秩路径下颜色输出补齐了与高位路径相同的裁剪，且低秩 DC 分量从 rank 纹理取半精度值，与标准路径保持同精度。

**加载时间的实测结论**（同一份训练模型导出的标准 QPLY（$r=45$）与低秩 QPLY（$r=7$）双臂对照，garden、truck、drjohnson 三场景，每场景 5 轮冷启动取中位数）：

| 场景（点数） | 标准 QPLY（$r=45$）总首帧 | 低秩 QPLY（$r=7$）总首帧 | 其中属性解析+重建：标准 / 低秩 |
| --- | ---: | ---: | ---: |
| garden（0.610 M） | 5.99 s | 7.26 s | 3.71 s / 5.81 s |
| truck（0.273 M） | 3.64 s | 7.72 s | 1.69 s / 5.18 s |
| drjohnson（0.432 M） | 5.29 s | 6.91 s | 2.85 s / 5.10 s |

结果表明：在该设备的加载链路上，低秩臂的"属性解析+重建"段与总首帧均**长于**标准臂，即共享基相关的额外成本没有被逐点系数解析量的下降覆盖。因此本文将低秩 QPLY 的收益定位在**存储与传输体积**（同一模型 14.65 MB 对 25.5 MB 的对应档，见 7.3 节），不把它表述为加载期的加速手段。两臂在渲染期的帧率处于同一水平，该结论不影响第 7 章的帧率对比。无论采用哪条路径，低秩相关计算都只发生在加载期或帧内求值循环中，渲染期的纹理布局与着色路径与标准三阶 SH 一致，不引入额外的神经网络推理。

## 6.5 解析器与格式兼容性

解析端需要处理三个层面。

**第一是格式识别。** 解析器通过检测文件头中是否同时存在各阶顶点元素、量化码本与可选的共享基关键字，在标准 PLY、标准 QPLY 与低秩 QPLY 三种格式之间分流：不含量化码本时进入标准 PLY 路径；含码本但不含共享基时进入标准 QPLY 路径；同时含码本与共享基时进入低秩 QPLY 路径。三条路径最终汇合到统一的纹理打包与求值流程。

**第二是属性命名的兼容性。** 不同训练与导出工具对同一几何或外观属性采用的属性名并不统一，尺度、旋转、DC 颜色与不透明度等字段在头部命名上均存在多种变体。解析器对每类属性维护一组命名别名并按优先级逐一匹配，否则会出现解析失败或属性值错位；例如旋转四元数可能以 `rot_0` 至 `rot_3` 或 `rotation_0` 至 `rotation_3` 等形式出现，SH 系数也可能按颜色通道分段或按系数序号交错排列。

**第三是纹理尺寸与跨设备兼容性。** 对比方法的 WebGL 实现把场景级 SH 系数组织为单张 8192 像素宽的浮点纹理，并在正式数据上传前以 1×1 全零纹理占位；在本文的移动端测试中该纹理未能成功上传，着色器只能取到占位数据，DC 与各阶 SH 系数一并缺失，画面退化为无颜色输出。本方法将 SH 系数按颜色通道拆分为三张宽度为 2048 的整型纹理（颜色缓存路径同样使用 2048 宽度），单张纹理在尺寸与格式上均处于移动端 WebGL 的常规支持范围，在相同设备上可正常渲染（跨设备验证见 7.7 节）。需要指出的是，SH 纹理高度随高斯数量线性增长，极端点数下总尺寸仍可能触及部分低端设备的最大纹理尺寸限制；当前实现还限制单场景仅含一个带 SH 数据的 Splat 对象以维持索引对齐，多对象合并渲染有待后续扩展。

对于不含量化码本的标准 PLY（含完整 DC 与 45 个 rest 系数的原始导出），解析器同样提供兼容路径：读取全部 rest 系数并按颜色通道分段打包进整型纹理，使系统既能加载压缩后的 QPLY（标准或低秩），也能兼容未压缩的标准训练产物，便于第 4、5 章的消融实验通过同一渲染入口做可视化检查。

## 6.6 系统集成与部署

渲染端基于开源库 gsplat.js 扩展集成而非从零实现。集成工作可分为六组，其中除部署配置对应的开关外，其余诊断与实验开关在缺省构建中全部关闭。

1. **格式与加载**：三格式识别；低秩系数 rank 纹理与共享基 uniform block 的加载、绑定与自证；加载期按配置决定是否展开 45 维。
2. **渲染路径**：片元颜色生产遍与半精度颜色缓存纹理；主 pass 顶点按索引取色；低秩片元分支按秩累加共享基；以及"单 splat 预处理遍 + 多渲染目标"分支（几何与颜色分别写入两个附件，并按排序槽位写入以保持顺序）。其中两处工程缺陷值得记录：多输出程序必须显式声明输出位置，且多输出与单输出程序需分开编译，否则在 ANGLE 路径上会报输出类型不匹配；此外在生产遍绘制前若误切回主 pass 着色程序，会形成对同一颜色纹理的读写反馈环，导致整帧绘制调用被跳过、画面全空。
3. **编译期门控与运行期自证**：跳过逐点变换、颜色变换恒等等优化以编译期宏实现，且仅在运行期自证结果与配置一致时注入；低秩宏（秩上限、rest 维度、共享基块长度）与文件头一致；每轮结果回传实际生效的配置标识，使"报告里的配置"与"实际跑的配置"可自动对齐。
4. **测帧与计时设施**：离屏帧缓冲目标（把渲染定向到指定尺寸的离屏帧缓冲区，绕开屏幕刷新率上限与界面开销）；统一像素协议（各臂强制同一渲染分辨率并记录其来源标记）；每帧分段计时（绘制前准备、绘制提交、绘制后处理、SH 纹理与过绘制等分段）；GPU 同步与计时器扩展不可用时的回退策略；以及计时地板标定，用于判定帧率读数是否已被驱动最小间隔钳制。
5. **可用性工程（浏览器端查看器）**：修复了初始版本的黑屏（根因是近/远裁剪面设置不当导致场景被整体裁掉）；补齐全屏布局；实现等比裁切填充（按目标分辨率计算视口并采用覆盖式缩放，避免不同宽高比下的拉伸与留白）；实现增量式轨道控制（明确旋转与缩放的映射方向、限制俯仰角范围）；加入加载遮罩；并新增两类自证开关，回传视图状态与界面自检结果，使查看器问题能定位到具体环节而不依赖主观描述。
6. **其它支撑改动**：排序侧视锥裁剪与分辨率缩放；单场景最大 splat 尺寸限制；WebGL 2.0 能力探测与失败回退；GPU 帧计时器封装；帧捕获与图像比对工具；PLY 加载器的中止信号支持；与对比基线一致的相机口径（同一组外参、同一焦距 1159.588，并加入相机一致性测试）。

**与加载期推理类方案的对比。** 与需要加载阶段神经网络推理的方案相比，本方法的加载路径完全确定：解析 QPLY 头部 → 查表反量化（含低秩处理）→ 打包纹理并上传 GPU，全程不需要逐点神经网络推理，也不需要计算着色器。编码器侧的差异同样明显：对比方法的模型采用码流压缩 + 向量量化 + 逐点推理的组合，其解码与推理耗时集中在首帧；本文的压缩产物为可直接解析的量化 PLY，首帧开销由文件体积、解析强度与上传带宽共同决定。两类方案的端到端首帧对比见第 7 章。

## 6.7 本章小结

本章完成了第 4、5 章压缩产物的统一部署出口。QPLY 在 reduced-3DGS 量化 PLY 的基础上兼容扩展，支持标准 QPLY 与内嵌共享基矩阵的低秩 QPLY 两种变体，解析器按文件头关键字自动区分三种格式。渲染管线提供两条三阶球谐求值路径（缺省顶点求值 / 颜色缓存片元求值）与两条低秩处理路径（加载期展开 / 渲染期按秩累加），四条路径的组合由开关显式选择并自证生效，其中颜色缓存路径在真机上带来约 1.43 倍的吞吐提升，而低秩的价值主要体现在模型体积而非加载时间。
