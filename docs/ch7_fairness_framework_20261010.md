# 第 7 章 · 公平性判断框架 + 历史测试逐族判定（2026-10-10）

> 这份文档回答两个问题：**(1) 我凭什么判"公不公平"；(2) 截止现在这些测试，哪些证据仍然成立。**
> 结论一句话：**口径（同一把尺子）基本公平；但"工作量等价"这一维度上，现有证据比想象的弱**，
> 因此**跨臂倍数**类结论要降级为区间或撤回，而**我们内部的消融**类结论不受影响。

## B. 为什么"工作量等价"这一维弱（这直接回答"不抓帧怎么知道"）

**(1) `covered` 是同一口径，但它证不了"画出来了"。**
- 我们：`bench-measure.ts:770 readCoveragePct()` = `frameRender()+gl.finish()` → 从离屏 FBO `readPixels` → **stride=8 网格**、判据 **`alpha > 0`**。
- Flux：`render_shared/main.js:2513-2519` = **stride=8 网格**、判据 **`alpha > 0`**（读 `gl.canvas.width`）。
- ⇒ 方法一致（可比），但判据是**alpha**：一块被 `clear` 成 `(0,0,0,1)` 的空 FBO 也会得到 **100%**。
- **实证**：今天 Flux 臂的离屏 FBO 读回 **RGB 全 0**（`framedump_ink_pct=0.00`、无损 PNG 恒 49,464 B），
  而它自己的 `covered` 仍报 **100.0%**。⇒ **`covered=100%` 不能证明该臂渲染进了那块 FBO。**

**(2) 即使点位/像素/机位全同，"每 splat 的着色成本"按设计就不同。**
- 我们：SH **3 阶 45 系数**；Flux：实际足迹**只到 1 阶**（`main.js:1272+` 的 2/3 阶代码是注释掉的）。
- ⇒ **"同 fps ⇒ 同效率"不成立**；只能说"**在各自声明的着色成本下**，fps 是多少"。

**(3) 因此"不抓帧"也能做的等价性核查，只有下面这些（今日已验证的部分）**：
`points` 逐位相同（273169）＋ flux `drawn=vertexCount`（同一数）＋ 同 `fbo:1600x1063`/`PVP1600,1063` ＋ 同 `pose`/`fx` ＋ 同 `res_mode=forced`。
**这些能证明"提交了同样多的高斯、覆盖同样多的像素、看同一个机位"，但证明不了"碎片着色量相同"。**

**(4) 补上这一维的最小代价（不抓全幅、不存 PNG）**：
在两臂**同一位置**各加一个 **ink 探针**：同一个 stride=8 网格上数 **`RGB>8`** 的样本 → 报 `ink_pct`。
- 我们：`readCoveragePct()` 里顺手多一个计数（~5 行，只多一次遍历，同一份 buf）。
- Flux：`main.js:2513-2519` 那个已有循环里多一个 `rgb>8` 计数（**该块已经是本文为了对照而加的仪器代码**，~3 行）。
- 该探针**确定性**（我们今天的帧三轮 base64 逐字节相同 ⇒ 同一机位的画面可复现），可直接作为跨臂"工作量等价"的证据，
  且**不需要 framedump**（也就绕开了 Flux 抓帧抓不到的问题）。

## C. 历史测试逐族判定（保留 / 降级 / 撤回）

|---|---|---|---|

| **我们内部 A/B/C 消融** | `strip_ct`、`P7`(prep)、`shfmt`、`slot`/`mrt`、`lrmp`、LR 预算 | ✅ **保留** | 同会话/同记录/同臂/单变量，**同记录 3 轮散布 ×1.00–1.02**（今天 `p7prep` A/B/C ×1.00–1.01 为证） |
| 分辨率/HL 扫描 | `r1600/r2400/r3200/r4096` | ✅ 保留（同臂单调量） | 同一臂内，不涉跨臂 |
| **ours vs Flux 跨臂倍数** | 3.70× / 1.95× / 1.77× | ❌ **撤回**（跨臂离屏 fps 不再作对照） | 见 `ch7_plan_next_20261010.md` §2–§3：Flux 臂在离屏协议下**不向被测 FBO 输出画面**（首末帧 `ink=0.0%`，两端复现），且两臂计时窗口构成不同源 |

## D. 以后写进方法的硬性口径（建议）

1. **同会话交替**：A → B → A′ → B′（A/A′ 互为频率锚），**≥3 轮**，报**中位数 + 极差**，**报区间不报倍数**。
2. **有效性闸门**：`cpu_ms`（= EL/SMP）明显偏离稳区 ⇒ **整轮作废**（既有 `BANDmid` 判据的同一类现象）。
3. **强制声明**：`offscreen_fps_source=wall-clock`、`ext=0`（移动端无 GPU 计时器）、`batch` 的排空入窗、**跨臂 `frame_ms` 不可互减**。
4. **工作量等价改用 ink 探针**（§B.4），不再依赖 `covered`（alpha 判据过弱）、也不再依赖跨臂全幅抓帧。
5. **不同时声称"同效率"**：两臂 SH 阶数/精度/混合不同，只能报"各自成本下的 fps"。
