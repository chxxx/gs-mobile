## 1. 三行结论

1. **方案 B（`shcache=frag`）在四台设备/环境上都显著赢 BASE**：Gen2/Adreno740 **1.43×**、Mali-G925 **1.40×**、Gen3/Adreno750（微信）**1.22×**；
2. **阶段 1（`lr=1` 渲染期低秩）是"设备相关"的结果**：Mali **+26.6% ✓**、Gen3 **+0.8%（打平）**、Gen2 **−6.5% ✗**；
3. **颜色正确性过关、显存减半以下**：桌面闸门 **LR vs BASE = PSNR 60.04 dB / SSIM 0.999863 / 最大 5 级 / 无 >8 级像素**；
   `lr=1` 不创建 3 张全 SH 纹理 ⇒ SH 相关显存 **58.6 MB → 19.5 MB**（**1/3**）✓。

## 3. 机制读数（为什么"设备相关"）

`lr=1` 把每点的 SH 取样 **6 → 2 次**，代价是**基累加**：`Σ_j a_j · Σ_{k=1..15} Y_k(d) · B[j,k-1,c]`
= **7×15×3 = 315 次乘加/点**（610k 点 ⇒ ~1.9 亿 MAC/帧）＋每点 ~315 次**动态索引的 UBO 读取**；
对照 packed 路径 = 6 次取样 + 24 次 unpack + ~45 次乘加。
⇒ 收益 = (省 4 次 TMU) − (加 ~270 次 ALU) ⇒ **在 Mali 上为正（+26.6%）、Adreno 740 上为负（−6.5%）、Adreno 750 上约等于零（+0.8%）** ✓。

## 4. 加载期指标（**当前不可用**，需要改协议）

`parse_ms` / `first_frame_ms` 在四台机上都是**跨会话噪声**（同臂不同会话可差 1–2×：Mali `frag` 3781 vs `base` 2201；
Gen3 同批 `frag` 4063 / `lr` 5768 / `lr-frozen` 4740 无单调性）⇒ **不能用它判低秩的加载期收益** ✗。
要干净测：把"低秩快速路径"当成一个可切换的**同会话臂**（如 `&lrload=1`）交替跑，像 fps 那样配对。
**结构性事实**（不依赖计时，可写进论文）：`lr=1` 跳过 `C@B` 与 48-half 打包、且不创建 3 张全 SH 纹理
⇒ SH 相关显存 **58.6 MB → 19.5 MB（1/3）** ✓。

## 5. 数据卫生与排除

- 分组一律用报告里的 `arm=`：`base` / `frag` / `frozen` / `lr` / `lr-frozen` / `tf_consume` / `flux`；
- `colorgate_20260930_202458.txt` 的 `arm=frag` 是**标签补 `lr` 之前**的（它是颜色闸门的 `lr` 抓帧，不是性能臂）✓；
- `lrchk_*`（`arm=-`、`fps=0`）是修复期的失败轮次 ✓（三个运行时缺陷的记录见下）；
- **环境不可比**：Gen3 那批是**微信/裸 GL ES**，Gen2 那批是 **Chrome/ANGLE** ⇒ 跨设备/跨环境只能报"各自环境内的配对差"，不能横向拼倍数 ✓。

## 6. 阶段 1 的修复链（都只能靠真跑暴露）

| # | 缺陷 | 现象 | 修复 |
|---|---|---|---|
| 1 | 加载期空 `shRgb` 以非 0 偏移 `set` | `RangeError: offset is out of bounds`（+230 ms） | 加长度判断 |
| 2 | 截断"SH 常量+辅助函数"切片时丢了切片自带的 `#endif` | 预处理器 `unexpected end of file found in conditional block` | 补回 `#endif` |
| 3 | 生产遍 draw 前切回主 pass 程序 ⇒ 主 pass 往自己要采样的颜色纹理上画 | 22× `GL_INVALID_OPERATION`、画面全空、`ok=0` | 不切回，保持生产遍程序 |
| 4 | DC 走 8 位基础色 | LR vs BASE 均值 0.53 级、PSNR 47.4 dB、SSIM 0.9987 | DC 迁到 rank 纹理第 2 纹素（half）⇒ 均值 0.058 级、60.0 dB |
| 5 | `lrRestRGB` 缺 `clamp(0,1)` | 58 px、最大 34 级的长尾 | 与 `evalSHRGB` 结尾逐字同源 |
| 6 | 模板串内注释含反引号 | `tsc` 语法错（第二次踩到） | 去掉并在注释里写明规则 |

**颜色闸门终值（桌面，同机位、全幅无损 PNG、320×213）**：
`LR vs BASE = 0.05819 级 / 最大 5 级 / >16 级 0 px / PSNR 60.04 dB / SSIM 0.999863`；
`LR vs FRAG = 0.00151 级 / 最大 1 级 / PSNR 76.34 dB`；对照 `BASE vs FRAG = 0.05843 级 / 60.02 dB / 0.999863`
⇒ **低秩臂的额外误差已低于 16F 颜色缓存自身的量化噪声** ✓。

## 7. 下一步（按证据排序）
