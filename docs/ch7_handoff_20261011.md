## 2. 这次修的到底是什么（根因 + 一行修复 + 证据）

> **论文数值口径（2026-10-10 更正，重要）**：`scenes/*r7 QPLY` 是**第 7 章的 r7 量化部署模型**；
> 已把**第 7 章**（表 7-4 本文方法行、表 7-6 DB 行、§7.4 画质/体积段与字段注）更新为新批次
> **29.76 / 0.908 / 0.244 / 0.311M / 7.5MB**（commit `thesis_project@95c2bd4`）。
> **第 4 章用的是未量化模型，值与文字均为原样（30.09/0.911/0.243），不要改**（曾误改并已还原）。
> 第 7 章的**设备侧列**（FPS/首帧/下载）仍建立在旧 PLY 上 ⇒ 见 T2。

**根因**：`bench-flux.ts` 在离屏测量前把**画布**清黑（视觉消歧）时设了 `clearColor(0,0,0,1)` 且**未恢复**；
Flux 的 `frame()` 绘制前只 `gl.clear(COLOR_BUFFER_BIT)`、**从不设 clearColor** ⇒ 它把离屏 FBO 清成 **alpha=1**
⇒ 其前到后混合 `blendFuncSeparate(ONE_MINUS_DST_ALPHA, ONE, …)` 的 **src 因子 `1−dstA` 恒为 0** ⇒ **绘制无可见输出**。
本文臂不受影响：它每帧自己 `clearColor(0,0,0,0)+clear`（`src/renderers/webgl/programs/RenderProgram.ts:2859`）。

**修复**：黑屏消歧之后**恢复** `gl0.clearColor(0, 0, 0, 0)`（`bench-flux.ts`，紧邻那段，**不可删除**）。

**验证（桌面与真机一致）**：`ink_pct` 0.0% → **99.3%**；`framedump` b64 49,464（常量黑图）→ **5,133,224**；
解码后 均值 111.06 / ink **99.04%**（本文臂同机位 116.69 / 99.42%）。

## 3. 已确立的读取规则（新会话必须遵守）

1. **输出门槛**：Flux 离屏行必须 `ink_pct ≥ 50`；**无 `ink_pct` 字段且日期 ≥2026-09-29 的行直接丢弃**（黑名单规则可复算：

2. **计时口径**：读任何离屏 fps 前先看 `offscreen_note` 里的 **`TWdrain` / `TWframe`**；
   `TWframe` 只覆盖帧段（会被合理性守卫拒收，`ok=0` 属预期）；**主数据用 `TWdrain` 且 `frames ≥ 20 & warmup > 0`**。

5. **取图链接不要带 `validateframe=1`**：本文臂 + `validateframe` + `framedump` 会**静默不提交**（服务端无 POST）。
6. **不要动 Flux 官方代码的渲染路径**；`render_shared/main.js` 里只有本文加的**只读仪器**。

   新增 pass/新臂必须过审计检查表：`docs/ch7_gl_state_audit_20261010.md` §4。
